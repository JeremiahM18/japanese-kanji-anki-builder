# v0.3.0-beta.1 N5 Automation-Reviewed Preview

## Release Decision

`v0.3.0-beta.1` is one exact, distributable **automation-reviewed preview**. It is not production/GA and is not human/device-QA approved.

Required public label:

> AUTOMATION-REVIEWED PREVIEW - HUMAN DEVICE QA NOT PERFORMED

The repository owner accepted the bounded residual risk in `PROD-REL-001` on 2026-08-01 because independent human QA, physical mobile-device QA, interactive screen-reader QA, listening/naturalness review, and stroke-sequence visual review are not realistically available for this release horizon. That constraint must remain visible; automation evidence must never be renamed as human evidence.

## Exact Scope

Included:

- core kanji deck, JLPT N5 only
- core word deck, JLPT N5 only
- the exact two APKG assets named and hashed in the version-3 release QA evidence packet
- the release QA evidence packet, CycloneDX SBOM, dependency-license inventory, checksum manifest, provenance attestations, SBOM attestations, and deterministic verification-material archive

Excluded:

- N4, N3, N2, and N1 core kanji decks
- N4, N3, N2, and N1 word decks
- additional-unverified kanji decks
- any claim that broader historic locks or completed review lanes are shipped by this release
- any production/GA, human-approved, device-approved, or accessibility-conformance claim

The exact commit, candidate run ID, APKG paths, release asset names, note/card/media counts, byte sizes, and SHA-256 values are release-time evidence. They live in the published `release-qa-evidence.json` asset because the APKGs must be rebuilt from the final protected-main commit before the tag is pushed.

## Automated Assurance Required

The preview is publishable only after all applicable automated controls pass on the exact release commit and exact downloaded draft assets, including:

- N5 Silver, Gold, Sapphire, Platinum, and Obsidian readiness for both core deck kinds
- tracked-source artifact and source-governance gates
- exact candidate commit, version, tag, deck scope, APKG name, size, SHA-256, note/card/media count, and release-asset-directory validation
- independent APKG ZIP, media-map, SQLite, collection-version, deck, field, note, card, and media-reference inspection
- managed-media provenance and integrity gates
- static accessibility review for the exact candidate scopes
- lint, typecheck, tests, documentation/lane audits, supply-chain, advisory, license, secret, SBOM, branch-protection, security-requirements, pre-release-trust, CI-smoke, and release gates
- hosted protected-main CI and CodeQL before tagging
- tagged Release workflow checksums, SBOM, provenance attestations, SBOM attestations, and constrained `gh attestation verify` for every published asset

## Explicit Accepted Limitations

The following are not performed and must remain recorded in the packet and release notes:

- desktop-anki-import-not-performed
- mobile-qa-not-performed
- screen-reader-interaction-not-performed
- listening-naturalness-not-performed
- stroke-sequence-visual-review-not-performed

The static and structural automation reduces risk but does not prove those interactions or perceptions. A future production/GA release still requires passed evidence for them unless governance is changed through a separately reviewed contract and risk decision.

## Publication Boundary

1. Merge the release-process change through protected `main` with hosted checks green.
2. Build both N5 APKGs from that exact merge commit under one isolated run ID.
3. Complete packet version 3 with commit-bound evidence and no hidden blockers.
4. Validate the packet and inspect both APKGs locally.
5. Create a local `v0.3.0-beta.1` tag at that commit, then create a draft GitHub prerelease targeting the same commit and upload only the packet plus the two declared APKG inputs.
6. Inspect the remote tag. If the draft did not create it, push the local tag; if GitHub already created the exact tag, dispatch `release.yml` with `--ref v0.3.0-beta.1`. This conditional avoids relying on undocumented tag-event timing while guaranteeing a tag-ref workflow run.
7. Let the tagged-ref workflow redownload and independently verify the draft inputs, run all gates, create the final bundle, attest and verify every file, then publish the prerelease.
8. Download the published assets, verify `release-artifacts.sha256`, and rerun the owner-authenticated hosted-security and full release-trust gates.
9. Close `SEC-P0-004` and `SEC-REQ-007` only through a post-release protected-main change backed by that hosted evidence.

Any mismatch, missing asset, extra input asset, nonzero gate, failed attestation, or tag/commit/version drift stops publication.
